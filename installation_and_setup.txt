     AI-DRIVEN INTRUSION DETECTION SYSTEM (AI-IDS) FOR POWER PLANT ICS
                      INSTALLATION & SETUP GUIDE

CRITICAL NOTICE:
This software is an AI intrusion detection research prototype evaluated on
simulated cyber-physical SCADA telemetry. It does not interface with live power
plant turbine hardware or real electrical switchgear.

1. System Prerequisites

================================================================================
1. SYSTEM PREREQUISITES
================================================================================
- Operating System: macOS (Apple Silicon or Intel), Linux (Ubuntu/Debian/RHEL), or Windows 10/11.
- Python: Version 3.10 to 3.14.
- Node.js: Version 18.x or higher with npm.
- Hardware: Standard development machine (2+ CPU cores, 4 GB RAM, 2 GB disk).

================================================================================
2. QUICKSTART INSTALLATION
================================================================================

STEP 2.1: CONFIGURE PYTHON VIRTUAL ENVIRONMENT
   Create and activate an isolated Python environment:
   $ python3 -m venv venv
   $ source venv/bin/activate        # Linux / macOS
   # (or .\venv\Scripts\Activate.ps1 on Windows PowerShell)

STEP 2.2: INSTALL PYTHON DEPENDENCIES
   $ pip install --upgrade pip
   $ pip install -r requirements.txt
   (Includes: pandas, numpy, scikit-learn, joblib, python-dotenv)

STEP 2.3: INSTALL WEB DASHBOARD DEPENDENCIES
   $ npm install

STEP 2.4: GENERATE SIMULATION CORPORA & TRAIN MODELS
   Generate the standardized simulation profiles (TRAIN, VAL, TEST, SHIFTED):
   $ python3 sim/generator.py

   Run the training, threshold calibration, and evaluation pipeline:
   $ python3 train_pipeline.py

================================================================================
3. OPERATIONAL EXECUTION MODES
================================================================================

To run the complete real-time system, launch three processes in separate terminal
windows (or background them):

TERMINAL 1: WEB DASHBOARD RELAY SERVER
   $ npm start
   (Launches the Node.js dashboard server at http://localhost:3000)

TERMINAL 2: LIVE TELEMETRY SIMULATION STREAM
   $ python3 stream_generator.py
   (Continuously produces live cyber-physical packets from seed 55 into live_stream.json)

TERMINAL 3: AI INTRUSION DETECTION ENGINE
   $ python3 detect.py
   (Actively scores packets using Random Forest, Isolation Forest, and LSTM,
    applying thresholds from thresholds.json and writing live_detection.json)

Access the UI at: http://localhost:3000

================================================================================
4. ARCHITECTURE & DATA CONTRACTS
================================================================================
- live_stream.json: Produced by stream_generator.py. Contains packet_id, node_id,
  timestamp, simulated_class, 37 numeric features, and physical telemetry metrics.
- live_detection.json: Produced by detect.py. Contains model probabilities,
  votes, consensus decision, physical metrics, and injected ground-truth label.
- stream_config.json: Written by the Web UI (/api/config and /api/inject) to
  control stream intervals (0.5s - 10.0s), streaming state, and attack injection.

================================================================================
5. REAL-WORLD LIMITATIONS & OPERATIONAL CONSTRAINTS
================================================================================
1. SIMULATION ENVIRONMENT: All telemetry is generated by sim/generator.py using
   autoregressive AR(1) state transitions and mathematical attack equations.
2. NO HARDWARE PCAP: The system does not inspect raw Ethernet frames (no Scapy,
   no promiscuous SPAN/TAP mirroring).
3. DOMAIN SHIFT VULNERABILITY: Under physical domain shift (1.5x measurement noise,
   diurnal load shift, benign switching transients), precision degrades from 91.2%
   to 52.8%, and Isolation Forest experiences elevated false alarms.
4. LATENCY BUDGET: Pure-NumPy tree traversals evaluate in under 1 millisecond per
   packet; however, deep neural network inference on embedded edge PLCs requires
   dedicated coprocessors.

================================================================================
6. MAINTENANCE & TROUBLESHOOTING
================================================================================
A. DASHBOARD STATUS SAYS "No data / detection engine offline":
   Ensure `detect.py` is running in another terminal. If detect.py is stopped,
   the UI safely indicates that the engine is offline.

B. RESETTING LIVE BUFFERS:
   If buffer files are out of sync, stop the processes and run:
   $ rm -f live_stream.json live_detection.json
   and restart stream_generator.py and detect.py.
